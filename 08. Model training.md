> Model training is required before the model prediction that produces
> the classified map. For Model training in FORCE, we can use either the
> Random Forest (RF) classifier or Support Vector Machine classifier (SVM). This step will produce a modelset for each response variable as an .xml file.

For this workflow, we will use an RF classifier. You can use SVM too, by changing it in the parameter file.

## Step 3: Fill up the parameter file

If you're planning to run multiple model predictions at a time, the filled up template needs to have the following on the top of
parameter file. This is a scenario where the multiple models are with the class weights changed (edit according to your own needs):

%SET%: 00001 00002 00003

%WEIGHT%: EQUALIZED PROPORTIONAL ANTIPROPORTIONAL

And then the OUTPUT section should be modified as such with {%SET%} and {%WEIGHT%}:

```
# OUTPUT
# ------------------------------------------------------------------------
# File for storing the Machine Learning model in xml format. This file
# will be overwritten if it exists.
# Type: full file path
FILE_MODEL = /home/docker/force/force/third/train_RFC_pbc_one_two_three/MODEL_CLASS_{%SET%}_{%WEIGHT%}.xml
# File for storing the logfile. This file will be overwritten if it exists.
# Type: full file path
FILE_LOG = /home/docker/force/force/third/train_RFC_pbc_one_two_three/FILE_LOG_{%SET%}_{%WEIGHT%}.log
```

Also, under the TRAINING section

```
# Type: Character / Float list. Valid values: {EQUALIZED,PROPORTIONAL,ANTIPROPORTIONAL} or ]0,1[
FEATURE_WEIGHTS = {%WEIGHT%}
```
Here the 00001 corresponds to EQUALIZED, 00002 to PROPORTIONAL, and 00003 to ANTIPROPORTIONAL.
So in this, three files will be created in the next step.

## Step 4: Create the required number of parameter files from the filled-up template parameter file

For this step, we will use the `force-magic-parameters` program see the [official FORCE documentation here][1]). 

Example files for both Linux and Windows can be found under the "Files" section of this component ("Model Training"). Remove the suffix _Linux or _Windows from this file to use with this current workflow.

*In Linux:*

In case of multiple model predictions to be carried out at the same time:

`sudo docker run -it -v /home/GIS/force:/data davidfrantz/force force-magic-parameters -o /data/train_parameters_RFC_pbc_one_two_three -c paired /data/parameter_train_rfc_pbc_one_two_three.prm`

`[sudo] password for birdlab:`

In the above, the tag-value *-c paired* is for ensuring that three models are created where 00001 corresponds to EQUALIZED, 00002 to PROPORTIONAL, and 00003 to ANTIPROPORTIONAL, and not 9 models where every number is matched with every class weight names.

Output:
```
2 replacement vectors detected
3 parameter files were generated
```

*In Windows:*

In case of multiple model predictions to be carried out at the same time:

`podman run -it --user root -v "C:\Users\GIS:/home/docker/force" davidfrantz/force force-magic-parameters -o /data/force/third/train_parameters_RFC_pbc_one_two_three -c paired /data/force/third/parameter_train_rfc_pbc_one_two_three.prm`

In the above, the tag-notation *-c paired* is for ensuring that three models are created where 00001 corresponds to EQUALIZED, 00002 to PROPORTIONAL, and 00003 to ANTIPROPORTIONAL, and not 9 models where every number is matched with every class weight names.

Output:
```
2 replacement vectors detected
3 parameter files were generated
```

## Troubleshooting

When using Windows, running the following code suggested [in a official FORCE tutorial][3] in step 5 will result in an error:

`podman run -it -v "C:\Users\GIS:/home/docker/force" davidfrantz/force for f in /home/docker/force/force/train_parameters_RFC/*.prm; do dforce force-train $f; done`

Output:
```
At line:1 char:148
+ ...  for f in /home/docker/force/force/train_parameters/*.prm; do dforce  ...
+                                                                  ~
Missing statement body in do loop.
    + CategoryInfo          : ParserError: (:) [], ParentContainsErrorRecordException
    + FullyQualifiedErrorId : MissingLoopStatement
```
The error occurs because I was trying to run a Bash-style for loop directly in PowerShell, which doesn't work. Podman expects the command after the image name (davidfrantz/force) to be in a format that the container's shell can execute.

Solution: Use `bash -c` to Run the Loop Inside the Container (as shown step 5)

Also, there is no command called `dforce` (It seems to be a defined function somewhere in the FORCE documentation).
