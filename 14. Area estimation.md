> After the creation of the final integrated maps, you would most likely want to estimate the area occupied by each class. Counting the number of pixels of each class and multiplying them by the size of a pixel can give you a false impression of the area
> estimates. It's always best to include the effect of accuracy of class in the area estimate, and get the error-corrected area estimates along with a confidence interval.

This can be done thrrough three steps.

# 1. Create input for force-map-accuracy module

The force-map-accuracy module will provide the error-adjusted area estimates for each land use/land cover classes along with some other useful metrics like producer's and user's accuracy. To use this module,
you need a couple of things as input - one is a csv file containing the number of pixels of each class within the final integrated raster, and the csv file containing the classes in the validation data (true class) in one 
column and the mapped class at the same location in the final integrated maps (may or may not be the true class). This can done by using the following R script.

Since Sentinel is higher resolution, it may be best to use it for accuracy assessment (can be for Landsat too). However, there will likely be many NA values where the validation data collected using the 
sample.gpkg (see section 12. Accuracy Assessment) file based on the Landsat input. We can check it.
