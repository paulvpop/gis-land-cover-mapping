> After the creation of the final integrated maps, you would most likely want to estimate the area occupied by each class. Counting the number of pixels of each class and multiplying them by the size of a pixel can give you a false impression of the area
> estimates. It's always best to include the effect of accuracy of class in the area estimate, and get the error-corrected area estimates along with a confidence interval.

This can be done thrrough three steps.

#### Table of contents

 - [1. Update the validation data](#1-update-the-validation-data)

The first two steps are linked in that you can run the first step and find out if the validation data is sufficient or not, and if proceed to Step 2 (and then Step 1 again) if not sufficient or continue with Step 1 after which you can proceed directly to Step 3.

# 2. Create input for the force-map-accuracy module

The force-map-accuracy module will provide the error-adjusted area estimates for each land use/land cover classes along with some other useful metrics like producer's and user's accuracy. To use this module,
you need a couple of things as input - one is a csv file containing the number of pixels of each class within the final integrated raster, and the csv file containing the classes in the validation data (true class) in one 
column and the mapped class at the same location in the final integrated maps (may or may not be the true class). This can done by using the following R script.

Load in the updated validation data before proceeding:

# 3. Run the force-map-accuracy model

Open the Linux terminal or Windows Powershell and run the following commmands.

First you can look at all the arguments available.

*In Linux:*

`sudo docker run -it -v /home/GIS/LULC/Reorganized_Rasters_Categorical/Top_Models_Organized:/data davidfrantz/force force-map-accuracy`

*In Windows:*

`podman run -it -v "D:\GIS_files\LULC\Reorganized_Rasters_Categorical\Top_Models_Organized:/data" davidfrantz/force force-map-accuracy`

```
count-file is missing!
Usage: force-map-accuracy [-h] [-v] [-i] [-o output-file]
        -c count-file -s sample-file -a pixel-area

   -h  = show this help
   -v  = show version
   -i  = show program's purpose

   -o output-file  = output file path with extension,
      defaults to './accuracy-assessment.txt'
   -c count-file  = csv table with pixel counts per class
      2 columns named class and count
   -s sample-file = vector file (or csv table) with predicted and reference class labels
      2 columns named label_map and label_reference
   -a pixel-area  = area of one pixel in desired reporting unit, e.g.
       100 for a Sentinel-2 based map to be reported in m², or
      0.01 for a Sentinel-2 based map to be reported in ha
```

Run the program:

*In Linux:*

`sudo docker run -it -v /home/GIS/LULC/Reorganized_Rasters_Categorical/Top_Models_Organized:/data davidfrantz/force force-map-accuracy -o /data/accuracy_assessment_sentinel.txt -c /data/map_acc_input_sentinel.csv -s /data/sample_file_sentinel.csv -a 100`

*In Windows:*

`podman run -it -v "D:\GIS_files\LULC\Reorganized_Rasters_Categorical\Top_Models_Organized:/data" davidfrantz/force force-map-accuracy -o /data/accuracy_assessment_sentinel.txt -c /data/map_acc_input_sentinel.csv -s /data/sample_file_sentinel.csv -a 100`

This will output the data in square metres (10 x 10 m for a Sentinel pixel). For Landsat, use 900 (30 x 30). For getting the outputs in square kilometres, divide by one million (1,000,000). So, instead of 100, use 0.000100 for output in sq. km instead of sq. m.
